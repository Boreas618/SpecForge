## 1. Step 1 — Drafter (speculator) design

**Backbone = SpecForge dense DSpark** (`specforge/modeling/draft/dspark.py::DSparkDraftModel` over `DFlashDraftModel`): a Qwen3-style dense transformer with DFlash dual-source-KV block-diffusion drafting, plus a low-rank **Markov** logit-bias head and a linear **confidence** (accept-rate) head. This is architecturally the same design as `RedHatAI/GLM-5.2-speculator.dspark` and `deepseek-ai/DeepSpec` (both `DSparkDraftModel(DFlashDraftModel)` = DFlash + vanilla-Markov + confidence). The heavy DeepSeek-V4 MoE draft (`dspark_v4.py`) is **not** used.

**Why dense (not target-matching MoE):** RedHat's dense GLM-5.2 draft reaches **mean accepted length 3.967** — the draft only consumes the target's *hidden states*, not its attention internals, so it need not mirror GLM's MLA+DSA+MoE. A target-matching MoE draft would be ~20 B params of new modeling with no vLLM/sglang deploy path.

Tiny vs the target, so FSDP/optimizer are cheap (contrast the 19.85 B V4 draft that forced CPU offload). Single size (§1.4).

### 1.2 Training recipe (loss + optimizer)

DeepSpec-canonical, identical across DeepSpec/RedHat (already the defaults in `scripts/train_dspark.py`):
- Loss: `0.1·CE + 0.9·L1 + 1.0·confidence`, `loss_decay_gamma=4.0`. (SpecForge's `l1` = `2·tv`; RedHat's `{"ce":0.1,"tv":0.9}` is the same objective up to that constant — keep as-is.)
- Confidence target = analytic accept rate `1 − 0.5·Σ|p_draft − p_target|`, BCE.
- `lr=6e-4`, cosine schedule, `warmup_ratio=0.04`, `weight_decay=0.0`, `max_grad_norm=1.0`, **bf16**.
- `max_length=4096`, `num_anchors=512` (start; try 1024 if the vocab-softmax objective tensor `[B, n_anchors, 8, 154880]` leaves headroom), **10 epochs**, **global batch 512**.

No 8 B variant — nothing in the field goes bigger, and UCloud's SpecForge-trained 5-layer draft already reaches mean accepted length 4.4-8.0 on code/math (greedy, live sglang). `hidden_size` is pinned to 6144 (shared embed/head, `dflash.py:274, 341-342`), so the only scaling axis would be depth — deferred, revisited only if accept length underperforms the references.

## 2. Step 2 — Implementation

Good news from recon: **most of the stack already exists.** No new drafter model code, no new target model code (sglang serves GLM-5.2 first-class). The work is config + template + porting the V4 trainer's multi-node hardening to the dense trainer + the real eval.

### 2.1 Target serving (online teacher) — REUSE, no new code
- `GlmMoeDsaForCausalLM(DeepseekV2ForCausalLM)` **is registered in sglang 0.5.14** (`srt/models/glm4_moe.py:1477`, in `EntryClass`) and is routed as a DeepSeek-DSA model (MLA + lightning-indexer, `index_topk=2048`). It inherits `set_dflash_layers_to_capture` / `set_eagle3_layers_to_capture` / `capture_aux_hidden_states` from `deepseek_v2.py:2799-2825`.
- SpecForge's `SGLangDFlashTargetModel` (`specforge/modeling/target/dflash_target_model.py`) already drives exactly these hooks and surfaces **both** the 5 aux hidden states (`aux_hidden_states` → `[8,23,39,55,70]`) and the final `last_hidden_states` needed by the L1/confidence losses. Embed/head keys are standard (`model.embed_tokens.weight`, `lm_head.weight`) — no key remapping (unlike DSV4).
- **MANDATORY capture-offset fix (aux `[1,19,38,57,76]` starts at 1):** `set_eagle3_layers_to_capture` special-cases `layer_ids[0]==1` by adding +1 to *all* ids (`deepseek_v2.py:2810-2814`) → it would capture outputs of `[2,20,39,58,77]` (77 = final layer, wrong). The HF backend and DSpark training semantics want `hidden_states[idx+1]` = output of layer `idx` = outputs of `[1,19,38,57,76]`. So the sglang backend **must call `set_dflash_layers_to_capture`** (consistent +1, no special-case), not the eagle3 variant. Verify with a small HF-vs-sglang parity check (`--target-model-backend hf` on a few sequences, compare captured tensors) before the long run.
- **Precedent — this exact stack is proven for GLM-5.2-FP8:** `UCloud-org/GLM-5.2-FP8-DFlash` was trained with **SpecForge** (FSDP2) against GLM-5.2-FP8 and is served via `sglang.launch_server --model-path zai-org/GLM-5.2-FP8 --speculative-algorithm DFLASH --speculative-draft-model-path … --tp-size 8` — direct evidence that SpecForge's trainer + sglang GLM-5.2 serving works end-to-end. (They used SpecForge's **offline** hidden-state pipeline; we use **online** per D3 — both are supported in the repo.)

### 2.2 Trainer changes (dense `scripts/train_dspark.py`)
The dense trainer works but was only smoke-tested at Qwen3-8B scale on the HF backend; the scaled/multi-node hardening lives in `train_dspark_v4.py`. Port surgically:
1. Use `--target-model-backend sglang` (default is `hf`).
2. **Port from `train_dspark_v4.py`:** NCCL long-timeout / default-PG-timeout override (a tp=16 753 B target load takes many minutes → otherwise trips the collective timeout), serial sglang weight-load host-RAM bounding (`SPECFORGE_SGLANG_SERIAL_LOAD`), and the DP-attention **dataloader shard-over-world** logic (currently `train_dspark.py` hardcodes `get_dp_group()`; under DP-attention it must shard over the whole world — the C3 edit already applied to the V4 trainer).
3. FSDP: the 3.8 B draft is tiny — `FULL_SHARD` (default) is fine and needs **no** CPU master-offload. `SHARD_GRAD_OP`/`no_shard` also viable (unlike the V4 draft). No grouped_mm needed (dense, no MoE); attention uses the FA4 flex path (§2.3).
4. Objective memory wall at vocab 154880: keep `num_anchors≈512` (the `[B, n_anchors, 8, 154880]` fp32 softmax tensors are the wall); raise only if a smoke test shows headroom.

### 2.3 Efficiency (task item: maximize efficiency / torch.compile)
- **FA4 (FlashAttention-4) flex-attention backend for the draft (R-ATTN-1).** The dense draft's dual-source-KV attention (`Qwen3DFlashAttention`, `dflash.py:42-134`) dispatches via `ALL_ATTENTION_FUNCTIONS[config._attn_implementation]`. Register a flex-attention path that calls the **FA4 backend** — per the attention-gym reference, `torch.compile(partial(flex_attention, kernel_options={"BACKEND": "FLASH"}))` invoked as `flex_flash(q, k, v, block_mask=block_mask)` with the dual-source `BlockMask` from `create_dflash_block_mask`. **This is newly viable because the draft has `head_dim=64`** (FA4 supports 64/128); the DeepSeek-V4 draft was forced onto Triton flex only because its `head_dim=512` hit `CUDA misaligned address` on FA4 (`EXECUTION_DOC.md §4i`). Caveats to validate on SM100/GB300: FA4 flex wants a flash-compatible `BLOCK_SIZE` (use `get_flash_block_size()`, likely (128,128), vs the Triton path's (32,32)); and FA4 disallows *captured dynamic scalars in a live mask_mod under `dynamic=True`* — we pass a **prebuilt** `BlockMask` (no live mask_mod), so this is fine, but confirm the Q/S-varying shapes don't force per-step retrace. Ref: `github.com/meta-pytorch/attention-gym/blob/main/examples/flex_flash_attention.py`.
- **torch.compile the draft — IMPLEMENTED + ON by default** (`SPECFORGE_COMPILE_DRAFT=1`, set in the run script; `=0` disables). `train_dspark.py` compiles the FSDP-wrapped model (`torch.compile(dspark_model, dynamic=True)`) AFTER FSDP. The flex block-mask HOP fails inductor lowering when nested in an outer compile on torch 2.11 (CantSplit / `unsupported operand &`), so `create_dflash_block_mask` and `Qwen3DFlashAttention.forward` are marked `@torch.compiler.disable` — mask construction + flex attention stay on their own (block-sparse, separately-compiled) path while the rest of the block (RoPE, RMSNorm, MLP, residual) fuses. **Validated** on 2-GPU FSDP: ~55 s first-step compile then ~0.1 s/step, varying seq lengths handled without recompile, finite loss+grads; eager path unaffected.
- Throughput is **target-bound** (753 B FP8 forward per step), so the dominant lever is **genuine DP** (§5): 16 unique data streams instead of dp=1 replication. Draft compute (~3.8 B) is small in absolute terms.
- bf16 training; FP8 only on the (frozen) target teacher.

### 2.4 Evaluation — DeepSpec accept-length, built into the training loop
Replace the probe eval with DeepSpec's accept-length methodology (fully reverse-engineered):
- **Algorithm:** per step the draft proposes `block_size` tokens (Markov-refined autoregressively within the block); **one target forward** over `block_size+1` tokens verifies; greedy acceptance (temp=0 ⇒ exact argmax match) with a +1 bonus token; **mean accepted length = Σ(accepted+bonus)/#proposals**, plus `accept_rate@k` per position, over the 9 datasets.
- **Datasets (DeepSpec, with caps):** gsm8k 500, math500 500, aime25 30, humaneval 164, mbpp 256, livecodebench 500, mt-bench 80, alpaca 500, arena-hard-v2 500. Build via DeepSpec's `eval_datasets/convert_eval_datasets_to_jsonl.py` (first turn only, `enable_thinking=False`).
- **Target execution:** DeepSpec's `eval.py` loads the target on a **single GPU** (impossible for 753 B). Instead run the verify forwards through **our already-sharded tp=16 sglang target** (reuse the training target engine), or a DeepSpec-style loop that calls it. This is the one genuinely new piece of eval code: a `GlmDSparkEvaluator` + accept-length loop wired to the sglang target. SpecForge's `dflash.py` already has a `spec_generate`/accept-length primitive to build on.
- **Cadence:** greedy, periodically during training (checkpoint boundaries) + a full 9-task sweep at the end. Log `eval/{dataset}/accept_length` + `accept_rate@k` to wandb. Goal probe = RedHat's 3.967.

### 2.5 Data precision (task item 5)

Deploy/pack is a downstream step (export to the vLLM `speculators` `config.json` schema so the drafter is one conversion from `vllm serve --speculative-config '{"method":"dspark","num_speculative_tokens":7}'`; note GLM-5.2 DSpark *inference* in vLLM is still landing — core DSpark merged 2026-07-01, GLM target wiring not yet confirmed, so deployment is best-effort/after-the-fact).
